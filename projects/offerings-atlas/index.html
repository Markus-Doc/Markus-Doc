An agent-run knowledge base for AI agent controls

Built 6 to 10 October 2026.

  • Read the full article ↗
  • Download PDF ↗
  • Try the questionnaire →
  • View the public sample ↗

I built a knowledge base of AI agent security controls that agents research, verify and keep current. It covers 151 platforms and tools, and an enterprise questionnaire answers a client's concerns from it with every citation checked against the knowledge base itself.

The atlas holds 6,644 researched findings across 44 controls, backed by 3,655 sources that are each tiered by who published them. An evaluator agent verified 20 cells in a showcase run, each with the stored page, its hash and a quote a pure function found on that page, and a recheck reproduced all 78 stored passages. It runs on my own machine through a local gateway, with no API keys, and 160 automated tests pass.

What it demonstrates

  • Agent design. Four agent roles with separate runs and narrow permissions, none of which checks its own work.
  • Knowledge engineering. One controls matrix projected into an OKF v0.2 tree, with frontmatter, chunks and an eligibility rule for agents.
  • Provenance. Every verified claim rests on a stored page, a hash and a quote that can be checked again without trusting the agent.
  • Evaluation. A labelled test set with deliberately altered claims, run against the real judge before it was allowed to write.
  • Governance. Facts run with no human gate, while advice for an enterprise goes through a pull request with named approver roles.
  • Cost engineering. Change detection by section hash, so only changed pages go back to a model.

Figures come from the project's own repository, evaluator runs and gateway proof log as of 10 October 2026. Verdicts describe documented capability, not tested deployments, and the client in the questionnaire is synthetic.
